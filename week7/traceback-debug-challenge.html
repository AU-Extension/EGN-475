Traceback debugging challenge

A traceback looks scary, but it follows a pattern. Read the last line to learn what went wrong, then find the last frame inside your own project to learn where. Ten real error screens, ten points each.

How to use this interactive
  1. Read the situation: what the user did when the error appeared.
  2. Step 1: click the frame that points to the line you need to fix. Frames from .venv belong to Flask and other libraries, not to you.
  3. Step 2: choose the cause and the fix.
  4. Press Check to see the explanation, then Next. The frame is worth 4 points and the fix 6 points.
  5. Some long library frames are shortened to keep the screen readable. Your own frames are shown exactly.

How to read a traceback

  1. Start at the bottom. The last line names the exception and gives the message.
  2. Read the frames from the bottom up and find the last frame in your project folder: app.py, db.py or a file in templates.
  3. Frames inside .venv\Lib\site-packages are Flask, Jinja or Werkzeug. The bug is almost never there.
  4. The line printed under your frame is the line to inspect. Ask: which value here is not what I expected?
  5. If you ask Copilot Chat for help, paste the whole traceback and the code around your frame. Then check its answer against these steps.
